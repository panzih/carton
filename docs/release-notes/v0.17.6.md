# carton 0.17.6

> **记忆终于看得见过程了。**

## 之前是什么样

每次任务结束，AI 会归纳一条记忆。但它当时拿到的输入只有两句话：

```
用户：打开设置，看看还剩多少存储空间
AI：任务完成，已经打开了设置并看到存储空间
```

而它的职责是提炼「常用应用」「这台机器的坑」「用户偏好」——
这些东西全在操作过程里，一条都没传给它。

模型面对这种输入只能回「无」，而代码里有兜底：**回「无」就把你的任务原文
抄进记忆文件**。所以之前那些记忆，很多其实就是：

```
（模型未给出归纳，自动记录的任务原文）
打开设置，看看还剩多少存储空间
```

这不是记忆。而且记忆文件只增不减，这类垃圾攒多了会挤掉真正有用的条目。

## 现在

**每一步都记进去了。** 主循环里的思考、动作、错误逐条进入记忆语境：

```
用户：打开设置，看看还剩多少存储空间
AI：「第 1 步 · 思考」先看看现在前台是什么
动作：「第 1 步 · 动作」打开应用 com.android.settings
AI：「第 2 步 · 思考」设置页打开了，找「存储」
动作：「第 2 步 · 动作」点击编号 12「存储」
AI：「完成」已看到剩余 48 GB
```

归纳器现在读的是这段完整过程，能真的看出「这位用户常进设置」这种事了。

## 三处配套修正

- **归纳时会带上已有记忆**，明确要求不重复写、能合并就合并。
  以前它不知道哪些记过，只能靠正文完全相同的字符串比较去重。
- **允许回「无」**。没有值得记的东西时诚实跳过，不再硬凑一条。
  接口返回空内容仍然按故障处理，不会被静默放过。
- **限制记忆语境的体积**：最多 120 条、单条 300 字。它原先和界面日志
  共用 300 条上限，过程进来之后不分开会把文件撑大。

## 你能看到的变化

任务结束时那条「记忆总结完成：xxx」里的标题会开始像真正的记忆，例如
「常用系统设置查看存储」，而不是复述你的原话。

如果某次任务确实没什么可记的，会显示「未写入：这次任务没有值得记的新内容」——
这是正常的，比以前硬写一条有用。
